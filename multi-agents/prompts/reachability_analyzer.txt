<TIPS>
Some tips for you to analyze the reachability of the call edge:

- Constructor.newInstance(args): All constructor args can taint the new instance
- Class.forName(): String parameter can lead to arbitrary class loading
 
- JDK Proxy.newProxyInstance(): Can only proxy interfaces, NOT concrete classes
- If target is concrete class method, JDK proxy cannot reach it directly
- CGLIB/ByteBuddy proxies can proxy concrete classes (but check if library is present)

- Polymorphism:
- Abstract methods: ALWAYS consider dynamic dispatch to all implementing subclasses
- Interface methods: ALWAYS consider all implementing classes in classpath
- Final methods: NO dynamic dispatch, only direct call possible
- Private methods: NO polymorphic dispatch, only direct class access

- Serialization:
- readObject() methods: Can trigger during deserialization even if not directly called
- writeReplace()/readResolve(): Can be called during serialization/deserialization
- Serializable classes: Constructor constraints may not apply during deserialization
- Transient and static fields are not restored from the stream; they hold defaults unless a callback assigns them
- Objects created inside a callback need not be Serializable; their state comes only from what the callback passes in
</TIPS>
