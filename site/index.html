Hunt new gadget chains.

Not the ones your JDK already killed.

Point GadgetHunter at a JAR, Spring Boot fat JAR or WAR. It derives taint rules from the bytecode, searches for deserialization chains, and ranks new routes through your code ahead of rediscovered public chains and routes the scanned build already blocks.

Built for people who report 0days.

Finding thousands of paths is easy. Deciding which ten deserve your evening is the work.

No handwritten taint config.

Callback roots, sinks, propagation and safe ignores are derived from your classpath. Missing dependencies and unimplemented APIs are reported, and a model can adapt rules to them, labeled as hypotheses.

Novel, known or dead.

Every candidate is labeled against a catalog of public gadget families and checked for mitigations in the scanned bytecode itself, so vendor backports and shaded copies are judged by what they actually do.

Real deliverables in.

Spring Boot fat JARs and WARs are split into application and library classes. Multi-release overlays, module-info and classes newer than the target runtime you point it at are dropped and listed, so you know exactly what was not scanned.

Built on peer-reviewed research.

GadgetHunter: Region-Based Neuro-symbolic Detection of Java Deserialization Vulnerabilities

Kaixuan Li, Jian Zhang, Chong Wang, Sen Chen, Zong Cao, Min Zhang, Yang Liu

Proc. ACM Softw. Eng. 3, FSE, Article FSE003 (July 2026)

Static analysis scales but drowns in infeasible paths and loses precision at reflection and dynamic dispatch; dynamic validation is precise but too costly to reach deep chains. GadgetHunter splits each gadget chain into regions by analyzability. Statically resolvable segments go through interprocedural taint analysis, dynamic boundaries are checked by an LLM, and the constraints of every gadget are composed into SMT formulas that decide whether the chain is feasible.

Four stages. Three need no model.

Your bytecode stays on your machine until you choose chains to analyze.

Prepare · prepare_scan.py

Normalize archives, index classes without loading them, and emit exact callback roots with validated sink and transfer rules.

Search · scan_candidates.py

Bounded taint search from protocol callbacks to effect boundaries. A timeout keeps complete chains and reports partial.

Triage · triage_candidates.py

Label novelty, effect and mitigations, cluster equivalent routes, and write a ranked review list. Nothing is deleted.

Analyze · multi-agents/main.py

Region-based LLM reachability and constraint extraction, solved with Z3, for the representatives you pick.

Novel

No catalogued family's core gadget appears. Reusable triggers like HashMap or BadAttributeValueExpException don't count against it.

Known

Uses a core gadget from a public family such as CommonsBeanutils, ROME or Groovy. A sanity check, rarely a new report.

Blocked

The scanned bytecode shows the route is dead, such as AnnotationInvocationHandler since 8u71 or the CC 3.2.2 functor guard.

Constrained

The effect needs more than the chain, such as a JNDI lookup on 8u191+ that needs a local ObjectFactory, or evidence couldn't be read.

Common JDK propagation is applied only where it can't hide an override, and ignores only where a closed-world bytecode check proves the call can't reach user code. Reflection boundaries are added when your code uses reflection. Library rules resolve only when that library is on the classpath. For APIs with no implementation on your classpath, an optional model pass proposes rules, and every candidate that relies on one is labeled as a hypothesis. Objects a callback reads from its own stream stay controlled, so calls on them are followed; a new ObjectInputStream built over controlled bytes is reported as secondary deserialization. Adaptive wrapper rules are added only after an independent bytecode validator proves them.

Get started.

Python 3.10+ and a JDK 17+ on PATH to run the analysis.

Point --java-home at a JDK that matches your target, Java 8, 11, 17 or newer; its class library models that runtime, so you scan the version you actually ship. No API key until the optional analysis stage.

Install.

git clone -b modern-scanning https://github.com/MarkLee131/GadgetHunter && cd GadgetHunter
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements.txt

Scan a deliverable.

Fat JARs and WARs are expanded automatically. Add --lib for dependencies that aren't bundled. Start with chains.review: one representative per cluster, in priority order, with every label explained in triage.json.

python scan_candidates.py --app /path/service.jar \
  --java-home /path/to/target-jdk --output scans/service \
  --collector fair --timeout 600 --heap-mb 6144

Analyze the best candidates.

Give the LLM and Z3 stage the review list instead of every candidate, so cost goes where new findings are likely.

cd multi-agents && export OPENAI_API_KEY=...
python main.py --chains-file ../scans/service/chains.review \
  --project-root /path/to/sources --batch --max-chains 50

Or use the browser workbench.

Upload archives, pick effect coverage, watch progress, and send ranked representatives to analysis. Everything runs on localhost.

python workbench.py --java-home /path/to/target-jdk --collector fair
# open http://127.0.0.1:8765

Know what a result means.

  • Candidates are leads, not exploits. FEASIBLE means the constraints are satisfiable, not that a payload runs.
  • A partial scan stopped at its budget. No result is a lower bound, not an all-clear.
  • "Novel" means not in the catalog, not necessarily unpublished.

Use it responsibly.

GadgetHunter ships no exploit generator. Its evaluation oracles use harmless in-memory markers, never commands or network callbacks.
