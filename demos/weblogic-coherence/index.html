WebLogic Coherence extractors vs. the default serial filter

loading evidence…

Each Coherence extractor class is read from the WebLogic Coherence jar and evaluated against two default WebLogic serialization filters. The allow/deny verdict is the decision the target's filter makes during resolveClass; the reachable sink is read from the gadget's own deserialization-reachable method. A gadget is reachable on a build only if its class is not denied by that build's filter.

Rediscovered on the unpatched build

UniversalExtractor resolves a method by name from its deserialized fields and invokes it by reflection. It passes the WebLogic 14.1.1 GA default filter and is denied on 15.1.1, where Oracle added it to the blacklist after the 14.1.1 release. This is the gadget behind CVE-2020-2883 and CVE-2020-14756.

Scope. These are known, already-patched CVEs. The result validates GadgetHunter's detection against ground truth on an unpatched build; it is not a 0-day, and the tool evaluates reachability and the filter decision only. It does not construct or execute a payload.
