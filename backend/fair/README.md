# Experimental fair candidate collection

Enable with `scan_candidates.py --collector fair` or `workbench.py --collector fair`. The default remains `stock`. Fair collection requires the compatible optimized backend and a host JDK compiler; it fails explicitly if unavailable, including in `--backend auto` mode.

This adapter replaces only Flash's post-analysis candidate collector. It keeps graph construction and the configured callbacks and rules. A suspended backward search retains its path, visited methods, taint state and child iterators between turns. Each sink advances for at most 64 cursor steps or a soft 20 ms interval, then gives the next sink a turn. There is one expanded cursor per sink. All initial controllable incoming edges are retained. This improves time to initial results across sinks, but does not provide fairness among branches within one sink.

Current edge ordering is `callback-distance-v1`: an initial breadth-first traversal from protocol roots records the minimum number of graph edges to each reachable method. Incoming callers with smaller distances are tried first, with application ownership and textual signatures breaking ties. The index ignores taint/types and never removes an edge. Later simplification can make its snapshot stale; unknown callers are tried after indexed callers. The journal records `edge_order` and `distance_index_methods`. Earlier measurements without these fields used direct-source/application/signature ordering; source fingerprints distinguish the versions.

Each incoming edge now uses `round-robin-deepening-v1`: finish depth 1, then 2, and so on up to the configured maximum. At each completed depth pass, move that edge to the back of its sink's queue; a parked completed pass has no live traversal frames. A partly expanded pass stays at the front until it finishes or exhausts its allowance. This lets later incoming edges try short paths while retaining only one expanded cursor per sink. Stop an edge earlier if a finished pass had no depth cutoffs. Increasing depth restarts traversal, sharing the same accumulated time allowance. This costs repeated work and does not guarantee globally shortest-first output. Existing checks and deduplication still apply. `next_caller` and `next_depth` expose the first pending cursor for diagnosis.

All searches share a dead-end memo (`typed-prefix-v1`) keyed by caller method and taint state. A state is recorded once its callers are fully explored and no path below it can be accepted: either none reaches a source, or every source path is rejected by the backend type check on its source-side prefix. The type check walks a chain forward from the source and decides each edge from the edges before it, so a rejected prefix rejects every chain that ends with it; the collector locates that prefix by binary search. A state is recorded only when its cycle checks never hit a method outside its own subtree, so the result does not depend on the path that reached it. States cut by the length limit keep the remaining length they were explored with. When simplification adds a new shortcut edge, every entry expires. The memo skips only work whose chains would be rejected, so it changes speed, not the set of chains a search can emit. The journal reports `dead_end_states`, `graph_changes` and per-sink `dead_end_prunes`.

The per-incoming-edge allowance is `floor(SINK_MAX_TIME * 1000 / controllable_edges)` milliseconds, matching the stock allocation for ordinary positive budgets. The adapter charges elapsed time while a cursor runs, including its checks and candidate emission; waiting for other sinks does not consume this allowance. Setup, journal writes and scheduling overhead are outside this internal allowance but inside the runner's wall limit. An individual graph expansion or backend predicate cannot be preempted at 20 ms. The process wall limit remains the outer bound. Extremely small allowances can expire without a search step and are reported as exhausted.

The adapter calls the bundled collector's own propagation, caller filtering, sanitizer filtering, type checking, simplification, similarity deduplication and chain emission methods. [`scan_rules/backend.py`](../../scan_rules/backend.py) checks the exact base-JAR fingerprint before compiling these sources and the string helper with `--release 17 -proc:none`. The overlay contains those classes and an analysis registry pointing to `FairSummaryDriver`; it precedes the unchanged base JAR. Each scan records the source and artifact hashes. A different backend must be audited before compatibility can be extended.

## Coverage and limits

`output/collector.json` is an atomic progress journal, also included in `stage1.json` and the workbench's scan details. It accounts for every configured sink: incoming/controllable edges, scheduled/finished/exhausted/pending edge searches, candidates, time to first candidate, active time and pruning counters. Cursor-step/cycle/taint/depth totals include only finished or exhausted cursors; active cursors are not included in those totals yet. Counters include repeated depth passes, so they do not count unique paths; an intermediate depth cutoff can be explored in a later pass. Journals update approximately every 250 ms between turns, so a terminated process can leave a slightly stale `running` snapshot.

The Python runner validates sink identity and accounting. Any exhausted edge allowance makes a normally returned scan `partial`. Missing, malformed or inconsistent completion metadata also cannot produce `completed`. Whole-process timeouts remain `partial`; only complete chain blocks are exported, even when the journal's last candidate count differs from the final output.

This is bounded heuristic search, **not exhaustive coverage**. Similarity pruning is order-sensitive, and Flash's simplification can add edges to the shared graph. Sinks snapshot their initial edges before traversal; nested expansions snapshot edges when entered. Different scheduling can therefore produce different candidates even without a timeout. Full stock/fair equivalence and a general recall improvement are not established. Keep separate stock comparisons and retain their evidence.

The test suite compares suspended and deepening traversal against independent bounded path enumeration on 3,600 graph/depth/quantum/strategy combinations, exercises invalid coverage accounting and budget exhaustion, and compares stock/optimized/fair output on scoped positive and negative Java fixtures. Actual HTTP integration covers both baseline and enhanced fair scans. See the [real-dependency evaluation](../../evaluation/README.md); candidate output is not a vulnerability verdict.
